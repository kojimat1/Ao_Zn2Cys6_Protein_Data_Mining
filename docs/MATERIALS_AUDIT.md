# Materials audit

## Included and directly usable

- Merged InterProScan output, two complete-proteome FASTA files, a CaoGD chromosome/sequence mapping table, the 233-ID list, and the protein/DBD sequence workbook used by the sequence-preparation notebook.
- Three sequence-region FASTA files used for motif, phylogenetic, and sequence-length analyses.
- Three aaComp CSV files and the DBD/protein-length table used for PCA-related analyses.
- The *A. oryzae* antiSMASH JSON file, GTF annotation, and 233-ID list used for BGC-proximity sensitivity analysis.
- Seven GTF files and two curated workbooks used for the AO090005001236 synteny analysis.
- Three reference Newick trees.
- Six related-species antiSMASH JSON files retained as supporting source data.

## Source-preparation input validation

- The SM00066 list contains 233 unique IDs.
- `aor0-5.faa` and `aor0-5_2.faa` each contain 11,902 unique protein records.
- Every one of the 233 SM00066 IDs occurs in both FASTA files.
- `aor0-5_merged.tsv` contains 113,601 rows, including 234 rows annotated with SM00066.
- The CaoGD mapping table contains 11,902 rows.
- The sequence workbook contains 234 data rows and the expected gene ID, description, chromosome, protein-sequence, and DBD-sequence fields.

The 234 SM00066 annotation rows are compatible with 233 unique proteins because one protein can contribute more than one DBD annotation.

The sequence-preparation notebook completed successfully with these inputs. Its general non-DBD rule generated 232 sequences because AO090012000182 has a C-terminal DBD and is excluded by that rule. The added helper script `scripts/finalize_non_dbd_fasta.py` applies the documented exception, extracts residues 1-581, and reproduces the deposited 233-sequence fixed non-DBD FASTA exactly.

## Files retained although not directly read by the supplied notebooks

The six related-species antiSMASH JSON files are not directly read by the final synteny notebook, which uses the curated XLSX summaries and GTF files. They are retained as supporting source data for the cross-species BGC assessment.

## Scope of reproducibility

The repository contains the analysis notebooks and inputs underlying the revised computational analyses. It does not reproduce execution of InterProScan or antiSMASH from the original genome files, and it does not include the R script that generated the supplied aaComp CSV tables. If the Data Availability statement promises regeneration from raw genome assemblies, those upstream workflows should also be deposited. For reproduction from the deposited intermediate data, the current package is sufficient when the notebooks are run in the documented order.
